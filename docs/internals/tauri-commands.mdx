## Overview

The Tempest desktop app is Tauri 2: a Rust backend with a React frontend that communicates over IPC. Every command the frontend can call is registered in a single `generate_handler!` list in `src-tauri/src/lib.rs` — **144 commands** in total. Definitions live in `lib.rs` itself and in a set of focused backend modules (`tasks.rs`, `automations.rs`, `claude_bridge.rs`, and so on).

Three properties hold across the surface:

- **Errors are strings.** Every fallible command returns `Result<T, String>` with a human-readable message. No structured error codes.
- **Blocking work runs on worker threads.** Git, PTY spawning, Docker, and network calls run on dedicated blocking threads so they never starve Tauri's bounded IPC worker pool.
- **Streaming uses `Channel`s.** Long-running output (terminal bytes, hook lines) flows through a `tauri::Channel` passed at call time rather than global events.

### `create_pty_session` in full

```rust
#[tauri::command]
async fn create_pty_session(
    app: tauri::AppHandle,
    session_id: String,                      // unique id, minted by the frontend
    cwd: String,                             // working directory
    rows: u16,
    cols: u16,
    command: Option<String>,                 // agent executable, or None for a bare shell
    args: Option<Vec<String>>,               // pre-assembled agent flags (resume, prompt, ...)
    sandbox: Option<SandboxSpec>,            // Hephaestus isolation spec
    policy: Option<SessionPolicy>,           // permitted agents, skip-permission flags
    db_isolation: Option<bool>,              // request a branched database for this session
    env: Option<HashMap<String, String>>,    // extra env from tempest.yml (denylist-filtered)
    worktree_add: Option<WorktreeAddSpec>,   // { project_path, name, existing_branch? }
    on_event: Channel<PtyOutputPayload>,     // streaming terminal output
    state: tauri::State<'_, PtyState>,
) -> Result<(), String>
```

The launch policy is enforced before any resource is acquired: a command not in `policy.permitted_agents` is rejected, and skip-permission flags are rejected when the project disallows them. When `db_isolation` is set and the workspace has a registered base image, the database branch is created in the background and delivered into the live session once ready.

## Events

Commands are request/response. Push updates flow as global Tauri events:

| Event | Payload | Emitted by |
|-------|---------|------------|
| `atlas:log` | `{ path?: string; line: string }` — one log line | Indexing, model download, and daemon management in `lib.rs` |
| `atlas:model-download` | `{ status: string; file?: string; progress?: number; loaded?: number; total?: number }` | `download_atlas_model` |
| `db:log` | `string` — one log line | Database branch operations (`dbiso`) |
| `automation:dispatch` | `string` — the automation id | The automation scheduler |
| `agent-hook` | `{ agent: string; session: string; event: string; body: string }` | The agent-hooks loopback server |
| `run:{session_id}` | `string` — one output line | `shell_run` (stdout and stderr interleaved) |
| `run:{session_id}:done` | No payload | `shell_run` when the process exits |
| `hook:{token}` | `string` — one output line | `run_hook` |

<Callout>
  Terminal output is **not** a global event. PTY bytes stream over the
  per-session `Channel` passed to `create_pty_session`, so each chunk is
  delivered directly to the session's own subscriber with no broadcast
  filtering.
</Callout>

## Examples

### Streaming a PTY session

```typescript
import { invoke } from "@tauri-apps/api/core";
import { Channel } from "@tauri-apps/api/core";

const channel = new Channel<{ session_id: string; data: string }>();
channel.onmessage = (payload) => {
  // Write bytes into the terminal emulator.
  term.write(payload.data);
};

await invoke("create_pty_session", {
  session_id: crypto.randomUUID(),
  cwd: worktreePath,
  rows: 24,
  cols: 80,
  command: null, // plain shell
  args: null,
  sandbox: null,
  policy: null,
  db_isolation: false,
  env: null,
  worktree_add: null,
  on_event: channel,
});
```

### Reading git status

```typescript
import { invoke } from "@tauri-apps/api/core";

interface GitStatusEntry {
  xy: string;     // two-char status, e.g. "M ", " M", "??"
  status: string; // dominant single char
  path: string;
}

const status = await invoke<GitStatusEntry[]>("git_status", { path: repoPath });
const dirty = status.length > 0;
```

### Building a database branch

```typescript
import { invoke } from "@tauri-apps/api/core";

const dockerUp = await invoke<boolean>("db_check_docker");
if (!dockerUp) throw new Error("Docker is not running");

await invoke("db_build", {
  conn_str: "postgres://user:pass@localhost:5432/appdb",
  method: "pgdump", // basebackup | pgdump | schema-only
  workspace_path: projectRoot,
  project_name: "my-app",
});

const branches = await invoke("db_list_branches", { workspace_path: projectRoot });
```

Because every command rejects with a plain string, a single `catch (e: string)` is all the error handling a caller needs — and because heavy work runs on blocking threads, a slow `git fetch` never blocks other IPC traffic.
