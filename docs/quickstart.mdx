Get Tempest up and running on your machine. The build process orchestrates Rust and TypeScript compilation, the React frontend, and Tauri bundling into installers.

## Prerequisites

<Steps>
  <Step title="Node.js 20 or later">
    Download from [nodejs.org](https://nodejs.org). Tempest uses Node for the React frontend build and npm scripts. Atlas requires Node 20+.
  </Step>
  <Step title="Rust (latest stable)">
    Install the latest stable toolchain via [rustup](https://rustup.rs). Tauri compiles the native backend with Rust.
  </Step>
  <Step title="Windows: WebView2 Runtime">
    Windows only. Download from [Microsoft Edge WebView2](https://developer.microsoft.com/en-us/microsoft-edge/webview2/). This is the rendering engine for the Tauri window.
  </Step>
</Steps>

## Installation and setup

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/tempestai-dev/tempest
    cd tempest
    ```
  </Step>
  <Step title="Install dependencies">
    ```bash
    npm install
    ```

    That is the whole setup: `npm install` runs postinstall scripts that automatically stage the Atlas bundle, the chat bridge sidecars, and the cloudflared sidecar. Nothing else to set up.
  </Step>
</Steps>

## Run in development mode

Start the dev server with live reload:

```bash
npm run dev
```

`npm run dev` runs `tauri dev`, which:

1. Starts the Vite dev server on `http://localhost:1420` and launches the Tauri app window
2. Reloads React components, TypeScript, and styles instantly — HMR shares port 1420
3. Recompiles and relaunches the Rust backend whenever `src-tauri/` changes

The app runs against the frontend dev server, not bundled assets.

## Build for production

Create installers and bundles:

```bash
npm run build
```

This command:

1. Runs `tauri build`: transpiles TypeScript, Vite bundles the React frontend to `dist/`, and the Rust backend is compiled
2. Bundles platform installers — on Windows: an NSIS installer, an MSI, and a portable `tempest.exe`, plus updater artifacts
3. Copies the NSIS setup executable and the portable executable to `dist-installers/` via `scripts/collect-artifacts.mjs`

The production build optimizes the Rust binary for size with link-time optimization (LTO), code-generation unit optimization, and symbol stripping.

## Build only the frontend

To bundle the React app without running Tauri:

```bash
npm run build:frontend
```

Output goes to `dist/`. This is useful for debugging frontend issues or testing the production bundle separately.

## Development tips

- **Frontend-only development**: Run `npm run dev:frontend` to start just the Vite dev server on port 1420 without launching the Tauri window
- **Preview production build**: Run `npm run preview` to test the bundled frontend in a browser
- **Tauri CLI**: Access Tauri commands directly with `npm run tauri <command>`. For example, `npm run tauri info` shows your development environment info

## Project structure

- `src/` : React TypeScript frontend code
- `src-tauri/` : Rust backend code
- `src-tauri/crates/hephaestus` : process isolation layer
- `src-tauri/crates/dbiso` : Docker database branching
- `packages/core`, `packages/crypto`, `packages/transport` : shared wire protocol, crypto, and transport for the mobile companion
- `apps/` : mobile companion + relay worker
- `web/` : marketing website (Next.js)
- `dist/` : Frontend build output (created by `vite build`)
- `dist-installers/` : Platform-specific installers (created by `tauri build`)
- `resources/` : Assets bundled into the app at runtime
