# Model Catalog

Every chat node picks a model from a portal picker fed by three sources: the bundled BYOK provider shortlists, the CLI agents' own `--model` alias lists, and a remote patch channel that can update the BYOK lists without an app release. This page is the full catalog as coded in `src/lib/chatModels.ts`.

For how the backends themselves work — API, CLI agent, and Warp — see [Chat Pane](/chat/overview). The short version: the **API (BYOK)** backend calls provider SDKs from the app's frontend via the Vercel AI SDK, the **CLI Agent** backend drives the vendor CLI headlessly through a per-turn Node bridge (auth is whatever the CLI is already logged into), and **Warp** is an experimental Rust gateway that routes `provider/model` strings in a single round trip.

## The models.json patch channel

The bundled tables above are a **floor**. On top of it runs a data-only patch channel that lives outside the app-version updater (`src/lib/remoteConfig.ts`), so a new model can ship by editing `config/models.json` and pushing, without cutting a release.

At startup, `startModelManifestFetch`:

<Steps>
  <Step title="Fetch">
    Fetches `https://cdn.jsdelivr.net/gh/tempestai-dev/tempest@main/config/models.json` with `cache: "no-cache"`.
  </Step>
  <Step title="Validate">
    `validate()` turns the untrusted JSON into a manifest patch. Anything malformed is dropped rather than coerced, unknown keys are ignored, and a bad manifest degrades to "no patch" — never a throw.
  </Step>
  <Step title="Merge">
    The patch is merged over the bundled floor: **provider-level replace** plus a **context merge by id**. A provider the patch names wins whole; a provider it omits keeps its bundled list.
  </Step>
  <Step title="Cache">
    The last-good raw manifest is written to `localStorage` under the key `tempest-model-manifest`.
  </Step>
</Steps>

<Warning>
  To add a model through the patch channel you supply that provider's full array — the patch replaces the named provider wholesale. An empty or partial fetch can never blank the UI, though: the merge can only add or replace whole providers, never remove one, so the bundled floor always stands underneath.
</Warning>

Resolution order: the bundled floor merged with the last-good cache is available before any network runs (new installs get the bundled lists; returning users get the last-fetched lists even offline), and a live fetch overwrites both. The fetch is silent on failure — the bundled or cached floor already works.

The channel is **explicitly unsigned**, by design: it carries display data only — model ids, labels, context numbers — nothing that grants privilege or influences behavior, so it needs no signature. Contrast this with the agent manifest, `config/agents.json`, which is verified with minisign because it carries CLI command strings and auto-approve flags. See [Agent manifest](/agents/manifest).

## Adding a model

<CardGroup cols={2}>
  <Card title="No release: config/models.json" icon="cloud-arrow-up">
    Edit `config/models.json` and push to `main`. The jsDelivr-hosted manifest is fetched at startup, validated, and merged over the bundled floor. Update the file's `updatedAt` stamp while you're there.
  </Card>
  <Card title="Release: the bundled floor" icon="package">
    Edit `PROVIDER_MODELS` / `MODEL_CONTEXT` in `src/lib/chatModels.ts`. This changes what ships in the app itself and goes out with the next release — use it for the initial catalog or when a bundled shortlist should change structurally.
  </Card>
</CardGroup>

<Callout type="info">
  BYOK provider keys come from your OS credential manager, entered once in Settings → API Keys — see [API Keys](/settings/api-keys). The experimental Warp backend is separate from all of the above: it has its own provider/model list (currently `openai/gpt-5-nano`, `openai/gpt-4o-mini`, `deepseek/deepseek-v4-flash`, `kimi/kimi-k3`, `openrouter/anthropic/claude-sonnet-4`) and is gated behind Settings → Experimental. See [Chat Pane](/chat/overview).
</Callout>
